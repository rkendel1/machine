── BROKEN ASSUMPTIONS / ANOMALIES (5)
  ✗ A per-token-only prefill model fails on cache hits
    evidence: 8 cache-hit calls evaluated 1 token(s) yet prefill took 34.7 ms on average; 7.23 ms/token predicts 7.2 ms (5× too low).
    so: Model prefill as fixed + per-token: 30.7 ms + 6.15 ms/token. The fixed part bounds what caching can save per call.
  ✗ Decode has a negative fixed cost
    evidence: decode_ms ≈ -32.1 ms + 36.14 ms × output tokens; the intercept is about 0.9 tokens' worth below zero.
    so: Physically a call can't save time, so the server's decode timer likely excludes some generated tokens (e.g. the first one, sampled at the end of prefill). Untested hypothesis; it doesn't affect the per-token slope, but don't read decode_ms/completion_tokens as exact for short outputs.
  ✗ Some runs stopped at end-of-sequence before max_tokens
    evidence: 1 run(s) generated fewer tokens than max_tokens without --ignore-eos.
    so: Their wall_ms measures answer length, not speed. The decode line uses actual completion_tokens, so it is unaffected; per-run tok/s comparisons are not.
  ✗ The model critic approves wrong answers
    evidence: 3 false accept(s) over 10 episodes (critic=model window=all cache=false temp=0); success 50% vs baseline 50%.
    so: A same-model critic is not an independent check here; its calls are pure cost unless success rises.
  ✗ Agent wall time did not reproduce across runs of critic=none window=all cache=true temp=0
    evidence: 2 runs: 2468 ms/task at 37 prompt tokens/call vs 4894 ms/task at 31 prompt tokens/call.
    so: Something outside the recorded settings changed between runs (server state, background load, thermals). Pooled effects for this config carry that variance; replicate before trusting them.
