## Broken assumptions and anomalies

- **A per-token-only prefill model fails on cache hits**  
  Evidence: 8 cache-hit calls evaluated 1 token(s) yet prefill took 34.7 ms on average; 7.23 ms/token predicts 7.2 ms (5× too low).  
  Consequence: Model prefill as fixed + per-token: 30.7 ms + 6.15 ms/token. The fixed part bounds what caching can save per call.
- **Decode has a negative fixed cost**  
  Evidence: decode_ms ≈ -32.1 ms + 36.14 ms × output tokens; the intercept is about 0.9 tokens' worth below zero.  
  Consequence: Physically a call can't save time, so the server's decode timer likely excludes some generated tokens (e.g. the first one, sampled at the end of prefill). Untested hypothesis; it doesn't affect the per-token slope, but don't read decode_ms/completion_tokens as exact for short outputs.
- **Some runs stopped at end-of-sequence before max_tokens**  
  Evidence: 1 run(s) generated fewer tokens than max_tokens without --ignore-eos.  
  Consequence: Their wall_ms measures answer length, not speed. The decode line uses actual completion_tokens, so it is unaffected; per-run tok/s comparisons are not.
- **The model critic approves wrong answers**  
  Evidence: 3 false accept(s) over 10 episodes (critic=model window=all cache=false temp=0); success 50% vs baseline 50%.  
  Consequence: A same-model critic is not an independent check here; its calls are pure cost unless success rises.
- **Agent wall time did not reproduce across runs of critic=none window=all cache=true temp=0**  
  Evidence: 2 runs: 2468 ms/task at 37 prompt tokens/call vs 4894 ms/task at 31 prompt tokens/call.  
  Consequence: Something outside the recorded settings changed between runs (server state, background load, thermals). Pooled effects for this config carry that variance; replicate before trusting them.

## Methods and limitations

- Lines (prefill vs evaluated prompt tokens, decode vs output tokens): Theil–Sen — median of pairwise slopes, intercept = median residual. Robust to warm-up outliers; no tuning constant.
- Intervals: 95% percentile bootstrap, 200 resamples, fixed seed 7. Same notebook ⇒ same beliefs.
- Success rates: Wilson score interval. Agent effects: difference of per-episode means vs the baseline config, two-sample bootstrap (unpaired; tasks are the same, so this is conservative).
- Agent configs use only runs over the full 10-task set; subset runs are excluded so success rates are comparable.
- Prefix-cache hit: cache_prompt=true and ≤4 evaluated prompt tokens. Modelled as paying only the fixed prefill cost.
- Status: parameters are KNOWN when the 95% half-width ≤ 15% of the estimate; effects are KNOWN when the interval excludes zero.
- Failure modes are rules over episode metrics, not clustering: solved; wrong answer (no format/tool errors: a planning error, since the calculator is exact); format loop (format errors until the step limit); format error then wrong answer; tool error.
- 40 agent episodes predate the tool_errors metric; their tool errors count as 0, so 'tool error' may be under-counted.
- Agent effects are measured on 10 arithmetic tasks with one small model; intervals are wide and the conclusions are about this setup only.
- The surrogate is two straight lines plus a constant. It extrapolates poorly beyond the measured prompt/output lengths and knows nothing about batching, GPU offload or other load-time settings.
